# BusRent — сайт оренди автобусів і мікроавтобусів + адмін-панель

Односторінковий сайт (лендінг) компанії з пасажирських перевезень та оренди автобусів
і мікроавтобусів, з **повноцінною адмін-панеллю**, **універсальним конструктором контенту**
та **зовнішньою безкоштовною базою даних** (Neon / Supabase / Vercel Postgres).

Стек: **Next.js 16 + React 19 + TypeScript + PostgreSQL (`pg`)**.
Уся верстка — власна CSS-система (змінні, адаптивність, glassmorphism у шапці), усі іконки — **SVG** (без емодзі).

> **Репозиторій:** https://github.com/MihailShupik/bus-rent — звідси проєкт імпортується у Vercel.
> **Відповідність ТЗ:** [`TZ-COMPLIANCE.md`](TZ-COMPLIANCE.md) — матриця «пункт ТЗ → реалізація → доказ».

## 2. Telegram-бот (заявки + адміністратори)

Бот **@bussite_bot** надсилає заявки з сайту всім адміністраторам і відповідає на команди.

**Розділ в адмін-панелі:** `/adminpanel/telegram`
- статус бота — реальні дані з Telegram API (назва, `@username`, чи працює токен);
- стан webhook + кнопки **«Підключити» / «Відключити»**;
- кнопка **«Надіслати тест усім адмінам»** зі звітом доставки по кожному адміністратору;
- **список адміністраторів**: додавання, редагування, приховування (без видалення) та видалення;
- покрокова інструкція, як додати нового адміністратора.

**Команди бота:**

| Команда | Дія |
|---|---|
| `/start` | привітання |
| `/id` | показує ваш Telegram ID (щоб додати себе в адмінку) |
| `/leads` | останні 5 заявок — лише адміністратори |
| `/stats` | статистика сайту — лише адміністратори |
| `/help` | довідка |

**Як додати адміністратора:** людина відкриває бота → тисне **Start** → надсилає `/id` →
в адмінці «Telegram-бот → Додати адміністратора» вписуємо ім'я та цей ID → «Надіслати тест».

> Telegram не дозволяє боту писати першим: доки адміністратор не натиснув **Start**,
> повідомлення йому не доставиться (у звіті буде «chat not found»).

**Токен** береться зі змінної `TELEGRAM_BOT_TOKEN`; якщо її не задано — токен можна
ввести прямо в адмінці (зберігається в `site_settings`).

### Що працює без webhook, а що ні

| Що | Без webhook | Чому |
|---|---|---|
| **Заявки з сайту → адміністраторам** | ✅ працює завжди | це вихідний запит із сайту в Telegram API, webhook не потрібен |
| **Команди бота** (`/start`, `/id`, `/leads`, `/stats`) | ❌ | Telegram має **доставити нам** повідомлення: у хмарі — webhook, локально — опитування (polling) |

**Webhook** (endpoint `/api/telegram/webhook`) на публічному HTTPS-домені підключається
**автоматично** при першому відкритті сторінки «Telegram-бот» — жодних ручних кнопок.
Якщо webhook уже вказано на інший домен, застосунок його не чіпає (є кнопки «Підключити/Відключити»).
Запити до webhook захищені секретним заголовком `X-Telegram-Bot-Api-Secret-Token`.

**Локальна розробка без публічного HTTPS** — режим опитування (Telegram не може достукатись
до `localhost`, тому замість webhook використовується polling):

```bash
node scripts/telegram-poll.mjs     # у другому терміналі, поки працює npm start
```

Скрипт кожні 2 секунди забирає апдейти й передає їх у той самий обробник, що й webhook,
тож команди бота працюють і локально. Оброблені апдейти не дублюються (offset зберігається в БД).

## 4. Безкоштовна зовнішня база даних (не на вашому сервері)

Додаток працює з **будь-яким PostgreSQL**, який віддає рядок `postgresql://…`.
База живе поза нашим сервером і не потребує обслуговування.

### Варіант A — Neon (рекомендовано, безкоштовний план)
1. Зареєструйтесь на [neon.tech](https://neon.tech) (є GitHub-логін, безкоштовний тариф).
2. **Create project** → назва, регіон (наприклад `eu-central-1`).
3. На сторінці проєкту → **Connection string** → скопіюйте рядок виду
   `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
4. Вставте його у змінну `DATABASE_URL` (локально — у `.env.local`, на хостингу — у налаштуваннях проєкту).

### Варіант B — Supabase
`Settings → Database → Connection string` → `DATABASE_URL=postgresql://...pooler.supabase.com:6543/postgres`.

### Варіант C — Vercel Postgres
Підключіть інтеграцію в проєкті Vercel — змінна `POSTGRES_URL` підхопиться автоматично.

### Створення таблиць і наповнення
Нічого робити вручну не потрібно: застосунок **сам створює всі 11 таблиць** і наповнює
їх стартовим контентом при першому запиті. Для явного запуску є:
```
GET /api/init-db          # створити схему + адміністратора
GET /api/seed             # додати стартовий контент (ідемпотентно)
GET /api/seed?force=1     # перезаписати стартові тексти
```

Перевірено: на **порожній** базі застосунок сам створив схему, додав 8 автобусів,
6 послуг, 8 переваг, 4 кроки, 54 налаштування і адміністратора.

### Підключена база (постійна, безкоштовна)

| | |
|---|---|
| Провайдер | **Neon** (безкоштовний план) |
| Проєкт | `Лендинг` / `quiet-pine-47095423` |
| Регіон | `aws-us-east-2` |
| Гілка / база | `production` / `neondb` |
| Підключення | пулер (`-pooler`) + `sslmode=require` |
| Рядок підключення | у `.env.neon` (файл у `.gitignore`) |

База **зовнішня** (обслуговується Neon, не нашим сервером), постійна (не має терміну дії,
на відміну від тимчасових тестових баз). Схема, стартовий контент і адміністратор
створюються автоматично при першому запиті.

### Перевірено на реальній зовнішній БД (Neon, поза нашим сервером)

Проєкт перевірено не лише на локальному PostgreSQL, а й на **реальній віддаленій базі Neon**
(`*.aws.neon.tech`, `us-east-2`, `sslmode=require`) — тобто рівно так, як буде на Vercel:

- застосунок сам створив у ній **11 таблиць** і наповнив стартовим контентом (8 автобусів,
  6 послуг, 8 переваг, 4 кроки, блок «Часті питання» + 3 елементи, 54 налаштування, адмін);
- вхід в адмінку, CRUD автобусів, конструктор блоків, завантаження фото
  (зберігається в таблиці `media` зовнішньої БД і віддається через `/api/media/:id`)
  та прийом заявок — усе працює проти віддаленої бази;
- **дані зберігаються між перезапусками** застосунку;
- наскрізні тести Playwright — **39/39** проти цієї зовнішньої бази.

Швидкий спосіб отримати тимчасову базу без реєстрації (для тестів/демо): сервіс
Claimable Postgres (`https://pg.new`). Для постійної роботи — безкоштовний проєкт на
[neon.tech](https://neon.tech) (0.5 ГБ), як у налаштованому вище `Лендинг`.

## 5. Локальний запуск

```bash
npm install
cp .env.example .env.local     # вкажіть DATABASE_URL
npm run dev                    # http://localhost:3000
```

Продакшн:
```bash
npm run build && npm start
```

### Змінні середовища
| Змінна | Призначення |
|---|---|
| `DATABASE_URL` | Рядок підключення PostgreSQL (Neon / Supabase / Vercel Postgres) |
| `ADMIN_EMAIL` | Email адміністратора (за замовчуванням `admin@bus-rent.ua`) |
| `ADMIN_PASSWORD` | Пароль адміністратора (за замовчуванням `busrent2026`) |
| `JWT_SECRET` | Секрет для підпису токенів адмінки |
| `TELEGRAM_BOT_TOKEN` | Токен бота від @BotFather (можна задати і в адмінці) |
| `TELEGRAM_CHAT_ID` | (необов'язково) додатковий чат для заявок |
| `NEXT_PUBLIC_SITE_URL` | (необов'язково) публічна адреса для webhook; на Vercel визначається автоматично |

> Уважно: після першого створення адміністратора зміна `ADMIN_PASSWORD`
> не переписує існуючий пароль. Щоб скинути — видаліть рядок у `admin_users`
> або змініть пароль через SQL.

## 6. Публікація на GitHub і деплой на Vercel (безкоштовно)

### Крок 1 — створити токен GitHub
GitHub **не приймає пароль** для API/git (це обмеження самого GitHub), тому потрібен токен:
`github.com` → **Settings → Developer settings → Personal access tokens → Tokens (classic)**
→ **Generate new token (classic)** → поставте галочку **`repo`** → **Generate** → скопіюйте `ghp_…`.

### Крок 2 — залити проєкт однією командою
```bash
GITHUB_TOKEN=ghp_ваш_токен ./scripts/push-to-github.sh bus-rent
```
Скрипт сам створить репозиторій на вашому акаунті та завантажить туди `main`.
(Токен використовується лише на час `push` і не зберігається в `.git/config`.)

Результат: `https://github.com/<ваш-логін>/bus-rent`.

### Крок 3 (варіант А) — деплой однією командою
```bash
VERCEL_TOKEN=ваш_токен ./scripts/deploy-vercel.sh
```
Скрипт підключить проєкт, пропише змінні середовища (з `.env.vercel`, `.env.neon` або `.env.local`)
і зробить production-деплой. Токен: vercel.com/account/tokens.

### Крок 3 (варіант Б) — імпорт через інтерфейс Vercel
1. [vercel.com](https://vercel.com) → увійдіть через GitHub → **Add New → Project**.
2. **Import Git Repository** → виберіть `bus-rent` → **Import**.
3. **Environment Variables** додайте:
   `DATABASE_URL` (з Neon), `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `JWT_SECRET`
   (за потреби — `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`).
4. **Deploy**. Після деплою перший запит сам створить таблиці й наповнить базу.

> **Важливо:** спочатку створіть базу на [neon.tech](https://neon.tech) (розділ 3) —
> `DATABASE_URL` потрібен ще до першого деплою.

## 8. Продуктивність і стійкість (важливо для зовнішньої БД)

Оскільки база зовнішня (мережа + serverless), доступ до даних оптимізовано:

- **Один запит замість семи.** Уся сторінка читається одним SQL-запитом: БД сама агрегує
  колекції в JSON (`json_agg` / `json_object_agg`).
- **Bootstrap один раз на процес.** Створення схеми й стартовий сидинг виконуються один раз
  (стан зберігається у `globalThis`, бо в Next.js кожен route-хендлер має власні модулі),
  а не на кожен запит. Було ~25 послідовних запитів на кожне відкриття сторінки.
- **Пул з'єднань** — до 10, з `idleTimeoutMillis`, сумісно з пулером Neon.
- **Нові поля налаштувань** автоматично додаються в існуючі бази, але правки клієнта
  не перезаписуються.
- **Логотип і SEO** застосовуються одразу після збереження (кеш метаданих скидається).

Замір: 40 одночасних запитів до сторінки на зовнішній Neon-базі — **40/40 успішно**,
середній час відповіді ~0.26 с (до оптимізації 20 запитів займали ~10 с).

### Безпека
Завантаження файлів (`/api/upload`) доступне **лише авторизованому адміністратору** (401 без токена),
дозволені типи зображень включно з SVG для логотипа.

## 9. Перевірка якості

```bash
npx tsc --noEmit     # типи: 0 помилок
npm run lint         # eslint: чисто
npm test             # 20 юніт-тестів (vitest)
npm run build        # продакшн-збірка
```

Наскрізні перевірки (Playwright) — у репозиторії, їх можна повторити на будь-якій базі:

```bash
npm i -D playwright-core        # один раз
npm start                       # в іншому терміналі
npm run test:e2e                # 62 перевірки: сайт, форма, галерея, адмінка, бот, безпека
BASE_URL=https://ваш-деплой npm run test:e2e   # перевірити вже задеплоєний сайт
```

Наскрізні перевірки (`tests/e2e.mjs`, 62 сценарії) проходять і на локальній базі,
і на **зовнішній Neon**: секції сайту, навігація, бургер-меню, галерея транспорту,
підстановка автобуса у форму, валідація й відправка заявки, відсутність горизонтального
скролу на 375/820/1024/1440 px, вхід в адмінку, усі розділи (включно з Telegram-ботом
і «Стан системи»), логотип, динамічне SEO, захист upload та адмін-API (401).
